# Claude 接入交接：静态道具与塔罗

2026-10-22：CODEX_PROMPTS 第 3、4 轮素材已交齐，可开始替换程序绘制的静态占位。此交接不表示运行时已接入新 PNG。

## 使用入口

1. 道具读取 `props/asset-manifest.json` 的 `assets`；塔罗读取 `tarot/asset-manifest.json` 的 `cards`。两份清单中的路径都相对 `game-art/fortune/`。使用 `native.path` 作为运行时静态图片源，共 29 + 22 = 51 项。
2. `master_4x.path` 用于复核或重新采样，不直接作为原尺寸精灵加载。`originals/`、`qa/` 和总览图均为源素材或检查资料；不要用递归 PNG 通配符加入固件资源包。
3. 保持目标尺寸。两种牌背分别为 44×72 和 82×135；完整牌面为 82×135。塔罗按清单的 `index` 映射，08 力量、11 正义；20 文件名是 `20-judgement.png`。
4. 引擎在牌面预留区画罗马数字与中文名。区域为 `number_rect_native=[6,5,70,8]`、`name_rect_native=[6,119,70,10]`；数组含义为 `[x,y,width,height]`。逆位由引擎旋转完整牌面及文字。
5. 卷轴正文安全区为 `[30,36,148,144]`。签筒只提供平视原图，由引擎生成 11 个倾角；铜钱、签子、牌、秤部件和打印纸的运动沿用设计与原型逻辑。
6. 卦符序号 0–7 对应 `乾、兑、离、震、巽、坎、艮、坤`，底爻至上爻的阳爻 bit mask 为 `7,3,5,1,6,2,4,0`。不要按二进制序号误排。

## 导出与验证

在 Windows PowerShell 中运行 `props/export-static-assets.ps1` 可以从保留的大图重新导出新增 PNG；支持 `-PropsOnly` 或 `-TarotOnly`。脚本使用 System.Drawing，并依赖同包的 `costume/export-art.ps1`。它不重新调用生成模型，也不覆盖既有龟甲。

已验证：51 项原尺寸及 51 项 4 倍版尺寸正确；新增道具硬边透明；铜钱方孔透明；八卦拓扑正确；22 张牌框一致、文字区为空；原尺寸最大不透明颜色数 33，4 倍版最大 34；既有龟甲与 C 造型未改变。生成源设计共 33 张（道具 11 + 塔罗 22），另保留既有龟甲大图。

仍需完成：将 PNG 接入原型和固件，制作 64 色索引资源（索引 0 透明），逐帧解码回比，检查动画中的道具位置、文字覆盖、逆位以及 RGB565 实机显示。对原有龟甲的抗锯齿边缘，按项目管线预混合 #0D0820。任何运动锚点均使用引擎处理实际视频所得的当前 `anchors.json`，不要从这批静态总览反推视频坐标。

本轮仅写入美术素材目录。原型、工具、固件、四份规范、Grok 视频及已有锚点均未由本轮修改。当前视频选择继续按既有 `grok-clips/selected-clips.json`，本静态素材包不携带或替换视频。

## 打包内容

`qa/static-art-delivery.zip` 保持 `game-art/fortune/` 内相对目录，包含原尺寸、4 倍版、源设计、提示词、清单、调色板、导出脚本、身份及定稿参考、交付说明和预览图。解压到项目的 `game-art/fortune/`，即可对应以上路径；其中参考图是归档副本，不要求覆盖当前项目参考图。包内 `props/qa/package-file-manifest.json` 列出全部载荷文件的 SHA256；包外 `package-verification.json` 和 `.sha256.txt` 记录 ZIP 逐项读回校验及整包摘要。
