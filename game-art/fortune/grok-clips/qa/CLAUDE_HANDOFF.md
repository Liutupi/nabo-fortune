# 给引擎侧的交接

项目：本仓库根目录。先读根 AGENTS.md 和 `game-art/fortune/ART_BRIEF.md`。

用户已选 C，两阶平涂定稿在 `costume/final.png`，10 张起始图在 `grok-start/`。目录现有 10 段原片和两段 v2，按 `grok-clips/selected-clips.json` 选择 10 段输入：N-TUBE 用 `N-TUBE_v2.mp4`、N-CALC 用 `N-CALC_v2.mp4`，其余八段用原片。v1 没有覆盖，不能继续用标准文件名误选这两条旧版本。各片均为 480×480、24 fps、4.04 秒、主视频 97 帧。源哈希在选用清单及两轮 QA 记录中。

美术侧已做动作和身份初检；两条 v2 的针对性问题已改善，当前不需继续向 Grok 返工。最新结论见 `qa/v2/REVIEW.md`；`qa/REVIEW.md` 下半部是 v1 历史记录。素材初检不是最终动画验收。

优先处理：

1. N-TUBE_v2 白帽相对首帧的位移粗测为横 0 / 纵 0.703 px（120 px 基准），明显改善，优先用这一版；后处理中仍要复核最终帧的位置，并检查 N-IDLE、N-SIGH、N-PRINT 的切换位置。不要把 N-WELCOME 作揖、N-NOD 点头等有意动作全部稳掉。
2. N-CALC_v2 角色左手掐指、视线朝上，v1 的目光游移问题在本轮顺序图和原尺寸抽查中已改善。用 v2 选取约 2 秒的完整循环，检查首尾眼神、嘴部和手势是否接得上。
3. N-SHELL 与 N-SHELL-TOSS 的龟甲口会随动作移动。`grok-start/start-frame-anchors.json` 仅为静态起始参考，不能作为已验证的视频锚点。按实际释放事件帧重新量取，并在正式 anchors.json 里说明坐标基准；若动画实现要求整段口坐标固定，先在交付说明中提出这一规范冲突。
4. 每条片长都有较多停顿，按 DESIGN 目标时长选段。N-SHELL-TOSS 主动作约 0.65–1.45 秒，N-WOW 约 0.8–1.7 秒，可作为定位参考；不要把所有片段直接整体加速。
5. 源文件有附加封面，视频解码明确指定 `0:v:0`。程序音效与源 AAC 音轨分开处理。
